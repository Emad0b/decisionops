# DecisionOps

DecisionOps helps you decide how to divide limited capacity when demand is uncertain. Use it to compare allocation plans and see how they balance the cost of spare capacity against the cost of shortages.

Temporal demand forecasting and cost-aware capacity planning.

Translate uncertain demand forecasts into capacity allocations under asymmetric costs and a shared resource limit.

## Implemented

- Synthetic demand with weekly/monthly seasonality, trend and occasional spikes.
- Seasonal-naive and multivariate Ridge forecasts with lagged inputs.
- Separate train, residual-calibration, model-selection and final-test periods.
- Empirical prediction intervals and measured coverage.
- Newsvendor critical quantile from under/over-provisioning costs.
- Exact greedy integer allocation for separable empirical convex costs under a shared budget.
- Compare forecast MAE with realised operational cost and shortage units.

## Run

Python 3.12 recommended. From this repository root:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -e ".[dev]"
$env:OPENBLAS_NUM_THREADS='1'
$env:OMP_NUM_THREADS='2'
python -m decisionops.cli --output reports
python -m pytest -q
```

On macOS/Linux, activate with `source .venv/bin/activate` and use `export OPENBLAS_NUM_THREADS=1`. Installing the package also provides the `decisionops` command. Run `python -m decisionops.cli --help` for options. No cloud credentials, paid services, external downloads or websites are required.

## Design and evaluation

Train on days 28–299, calibrate residual scenarios on 300–359, select models/policies on 360–419 and test on 420–599. Forecasts are one day ahead with observed prior-day inputs; residual scenarios preserve joint daily site errors. Costs are hypothetical: shortage 9 units, excess 1 unit, so the unconstrained critical quantile is 0.9. The shared daily capacity is 1,000. Marginal expected savings are decreasing for each site; allocating each next unit to the largest positive saving solves this particular integer convex allocation problem. The solver is tested against exhaustive enumeration on a small instance.

## Results

`results.json` contains MAE, interval coverage, decision cost and allocation limits. `decisions.csv` shows each held-out day/site forecast, interval, capacity and observed demand. `summary.md` compares policies.

Reports are generated by real local algorithm runs over **explicitly synthetic data**. They demonstrate methodology, not claimed company results. Seeds are fixed. Re-run on your machine; floating point, timings and dependency versions may differ. See [methodology](docs/methodology.md) and the generated reports for measured results. CI configuration is included; no remote CI execution is claimed.

## Limitations

Empirical residual intervals assume stable errors and do not guarantee nominal coverage; measured coverage is reported. Fixed synthetic costs are not business ROI. A single shared constraint and separable costs permit the greedy solution; lead times, minimum staffing, network constraints and nonlinear interactions require a different optimiser. No ranking reversal is manufactured: the lower-MAE model may also be the lower-cost model. The key demonstration is that decision policies must be evaluated on operational cost, not accuracy alone.
